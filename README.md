# Виджет ИИ-консультанта для сайта «Сибирь Проект»

Готовый комплект для запуска анонимного чат-виджета 24/7 с базой знаний (RAG) на основе разделов сайта, FAQ и прайс-ориентиров [sibirproekt72.ru](https://sibirproekt72.ru/).

## Состав проекта

- `index.html` — демо-страница с подключенным виджетом.
- `widget/widget.js`, `widget/widget.css` — встраиваемый виджет чата (vanilla JS/CSS).
- `server.py` — backend API: поиск по базе знаний + генерация ответа через LLM (OpenAI-compatible API) или fallback-ответ по найденным фрагментам.
- `data/knowledge_base.json` — база знаний (компания, контакты, услуги, цены/сроки, FAQ, калькулятор, процессы), собранная из открытых разделов сайта.

## Как это работает (RAG)

1. Пользователь задает вопрос в виджете.
2. `server.py` ищет релевантные фрагменты в `knowledge_base.json` (лексический поиск/BM25-подобный скоринг, без внешних зависимостей).
3. Найденные фрагменты передаются в LLM вместе с системным промптом и историей диалога.
4. Модель формирует ответ строго на основе контекста; виджет показывает ответ и источники (ссылки на разделы сайта).
5. Если `OPENAI_API_KEY`/`LLM_API_KEY` не задан, сервер возвращает fallback-ответ на основе найденных фрагментов базы.

## Быстрый запуск локально

Требования: Python 3.10+ (проверено на 3.12), без дополнительных пакетов.

```bash
python server.py
```

Откройте: [http://localhost:8000](http://localhost:8000)

Проверка API:

```bash
curl http://localhost:8000/api/health
```

### Включение генерации ответов через LLM (рекомендуется)

Windows PowerShell:

```powershell
$env:OPENAI_API_KEY="ваш_api_ключ"
$env:OPENAI_MODEL="gpt-4o-mini"   # опционально
# $env:OPENAI_BASE_URL="https://api.openai.com/v1"  # опционально, для совместимых API
python server.py
```

Linux/macOS:

```bash
export OPENAI_API_KEY="ваш_api_ключ"
export OPENAI_MODEL="gpt-4o-mini"
python server.py
```

Поддерживаемые переменные окружения: `OPENAI_API_KEY`/`LLM_API_KEY`, `OPENAI_BASE_URL`/`LLM_BASE_URL`, `OPENAI_MODEL`/`LLM_MODEL`, `HOST`, `PORT`.

## Встраивание виджета на сайт `sibirproekt72.ru`

1. Разверните backend (`server.py` + `data/knowledge_base.json`) на сервере/VPS/хостинге с Python (за HTTPS-прокси, например Nginx/Caddy). Убедитесь, что доступен endpoint `POST /api/chat`.
2. Разместите файлы `widget/widget.js` и `widget/widget.css` на доступном домене (можно рядом с backend).
3. Добавьте на страницы сайта перед закрывающим `</body>`:

```html
<link rel="stylesheet" href="https://chat.sibirproekt72.ru/widget/widget.css">
<script>
  window.SIBIRPROEKT_CHAT_CONFIG = {
    apiUrl: "https://chat.sibirproekt72.ru/api/chat",
    title: "Консультант «Сибирь Проект»",
    subtitle: "На связи 24/7"
  };
</script>
<script src="https://chat.sibirproekt72.ru/widget/widget.js"></script>
```

> Замените `https://chat.sibirproekt72.ru` на фактический адрес, где развернут виджет/сервер. Сервер возвращает CORS-заголовки (`Access-Control-Allow-Origin: *`), поэтому виджет можно размещать на основном домене сайта.

## Обновление базы знаний

База знаний хранится в `data/knowledge_base.json` — массив объектов:

```json
{
  "id": "unique-id",
  "title": "Название раздела",
  "url": "https://sibirproekt72.ru/...",
  "section": "Услуги|FAQ|Цены|Контакты|...",
  "tags": ["ключевые", "слова"],
  "content": "Текст фактов и ответов"
}
```

Рекомендации:
- Добавляйте отдельные карточки на каждую услугу, FAQ-пары, цены/сроки, условия и навигационные подсказки.
- Указывайте дату актуальности для изменяемых данных (цены, акции, сроки) и обновляйте при изменениях на сайте.
- Поддерживайте единый стиль формулировок и добавляйте синонимы в `tags` (БГ/банковская/независимая гарантия, КИК, ЭЦП и т.д.).
- После изменения файла перезапустите `server.py` (база загружается в память при старте).

## Соответствие требованиям ТЗ (анонимность и границы)

- **System prompt** в `server.py` задает роль, дружелюбный профессиональный тон, запрет на запрос/сбор/повтор персональных данных и алгоритм действий при отсутствии ответа (контакты компании вместо сбора данных пользователя).
- **Виджет** показывает уведомление об анонимном общении и не содержит форм сбора контактов.
- **Эскалация:** при отсутствии точного ответа бот направляет к официальным контактам компании (телефоны, email, часы работы, сайт).
- **Важно на стороне инфраструктуры:** отключить/минимизировать логирование содержимого чатов, ограничить доступ к логам, настроить срок хранения и не передавать данные в сторонние системы без необходимости. Поведение модели не заменяет настройки платформы и хостинга.

## Ограничения текущей реализации

- Поиск по базе знаний — лексический (без векторных эмбеддингов). Для больших объемов/сложной семантики рекомендуется добавить векторное хранилище (FAISS/Chroma/Qdrant и т.п.) и эмбеддинги.
- Без настроенного LLM API сервер работает в fallback-режиме (возвращает релевантные фрагменты базы), поэтому качество формулировок ответов ниже, чем при генерации.
- Для production рекомендуется: HTTPS, rate limiting, мониторинг, резервное копирование, защищенное хранение API-ключей, журналирование без персональных данных.
